# Hardware abstraction (`FW-HW`)

Board "Nixie Clock V4.5.1". Facts from photos and the 2026-11-06/07 measurements are listed. The annotated board diagram, part-by-part confidence and the measurement list are in [board.md](board.md).

## Known

| Part | Facts |
|---|---|
| MCU | ESP8285: ESP8266 core, 1 MB flash in-package, 26 MHz crystal, PCB antenna. Arduino FQBN `esp8266:esp8266:esp8285`. |
| LEDs | 60 × WS2812-style RGB (LED1–LED60), 6 tubes × 10 digits; LED1–10 under the tube at the silkscreen end, LED51–60 under the tube at the button end. Data is GPIO 13, color order GRB (pin-finder, 2026-11-06). Chain and digit order are in FW-DSP-002. |
| RTC | GC1307 (DS1307-compatible, I²C address 0x68), 32.768 kHz crystal, CR1220 cell, 5.1 kΩ pull-ups. SDA = GPIO 4, SCL = GPIO 5: of all pairs of GPIO 4, 5, 12, 14 only this one answered (FW-HW-010, 2026-11-07). GPIO 10 toggles once a second untouched, almost certainly the RTC's SQW output. |
| Buttons | 4 rear buttons, low when pressed. Pressed in order from the USB-C end they read GPIO 0, 2, 9, 16 (FW-HW-010). GPIO 0 is also JP1 pin 4, so holding button 1 at power-on should enter flashing mode (unconfirmed). GPIO 2 is a boot strap too, so holding button 2 at power-on may stop the clock booting. GPIO 16 has no internal pull-up and read high idle, so the board pulls it up. |
| Buzzer | Through a transistor, GPIO 15, on when high. It sounded on a plain level and on a tone, so a level is enough (FW-HW-010). |
| JP1 | Unpopulated 6-pin header, square pad = pin 1, nearest USB-C. Pin 1 = 5 V (never connect to an adapter), 2 = ESP RX, 3 = ESP TX, 4 = GPIO0, 5 = unidentified, 6 = GND (measured 2026-11-06; TX, RX and GPIO0 proven by talking to the boot ROM). Pin 5 idles near 3.6 V and is probably reset or enable. |
| Regulator | 3-leg SOT-23 between the capacitor banks. Single leg (away from the ESP) = 5 V in. Of the two legs toward the ESP, one is ground and the other the output. The output does not connect directly to any JP1 pin. |
| USB-C | Power only (5.1 kΩ CC pull-downs), no serial bridge. |

## Requirements

| ID | Requirement | Status |
|---|---|---|
| FW-HW-001 | The core (`firmware/core/`) has no Arduino or hardware dependency and compiles with `-Wall -Wextra -Werror` on the host and the device. | Done |
| FW-HW-002 | All GPIO numbers are compile-time constants in one place (`TUBECLOCK_LED_PIN`, `TUBECLOCK_RTC_SDA`, `TUBECLOCK_RTC_SCL`, `TUBECLOCK_BTN_1..4`, `TUBECLOCK_BUZZER_PIN`), set with `-D` flags by `build.sh`, which uses the CT-001's measured values unless a pin flag is named. A feature whose pin is undefined is compiled out, never guessed. So is a level: `TUBECLOCK_BTN_PRESSED_LEVEL=0\|1` and `TUBECLOCK_BUZZER_ON_LEVEL=0\|1` are required once their pins are set, and the build fails without them. GPIO 6, 7, 8 and 11 (flash) are refused at compile time; DOUT (FW-HW-009) leaves GPIO 9 and 10 free, and button 3 is GPIO 9. | Done (`-D` flags at the top of the sketch; `isUsableGpio` host-tested, `testPins`; a build with every flag set compiles). The measured values are in `firmware/README.md`. |
| FW-HW-003 | The LED driver is Adafruit NeoPixel, `NEO_GRB + NEO_KHZ800`. | Done: pin-finder byte order read as green, red, blue on 2026-11-06. |
| FW-HW-004 | A **pin-finder** build mode (`-DTUBECLOCK_PINFINDER`) walks candidate GPIOs and lights LED index 0..59 one at a time while printing the index on serial, so the LED pin, chain order and color order can be read off the clock. It MUST never drive GPIO 0, 2, 15 (boot straps), 6–8 or 11 (flash), or 9 and 10 (no reason to). | Done: `firmware/pinfinder/pinfinder.ino`, built by `build.sh -DTUBECLOCK_PINFINDER` (no Wi-Fi, no secrets). It walks GPIO 4, 5, 12, 13, 14 with one second a step: LED 0 with each color byte alone (color order), then every LED, printing `gpio=` `led=` `byte=`. `-DTUBECLOCK_LED_PIN=<gpio>` walks just that pin. Also left alone: GPIO 1 and 3, the serial port it prints on, and GPIO 16, which Adafruit NeoPixel cannot drive (`pinFinderMayDrive`, `pinFinderStep`, compile-time checked and host-tested, `testPins`). Run on the clock 2026-11-06: GPIO 4, 5 and 12 stayed dark, GPIO 13 lit the LEDs one at a time (GPIO 14 was not observed separately). |
| FW-HW-005 | The chain order measured by FW-HW-004 is written into `LedLayout` as a constant table in the core, with a unit test asserting `isValid()`. | Done (`LedLayout::ct001()`, `testLayoutAndRender`). Read at one frame per second from the user's video of one full pass; the group order, direction and zigzag are clear, but single LEDs were not all checked one by one. |
| FW-HW-006 | Buttons: in v1 a press on any of the four cancels an active attention flash (FW-ATT-011), nothing else. Each input is debounced in software (≥ 30 ms), polled from the loop, never blocking. Compiled out when `TUBECLOCK_BTN_*` are undefined. | Partial: core `ButtonDebouncer` (host-tested, `testButtons`), polled from every wait as well as the loop; any subset of the four pins works. A pressed level of 0 uses the internal pull-up (GPIO 16 has none, and the board pulls it up), 1 relies on the board's resistors. Pins and pressed level are measured (FW-HW-010). **Gap:** the cancel has not run on the clock (checklist 11). |
| FW-HW-007 | Buzzer: used only by the opt-in `beep` on attention flashes (FW-ATT-010): a ≤ 300 ms pattern, never continuous, driven through transistor Y1. Compiled out when `TUBECLOCK_BUZZER_PIN` is undefined. | Partial: driven at `TUBECLOCK_BUZZER_ON_LEVEL`, set off before the pin becomes an output, kept up to date from every wait so a slow request cannot stretch a pulse, and silenced when an OTA update takes over the loop. Pin and level are measured, and a level sounds it (FW-HW-010). **Gap:** the attention beep has not run on the clock (checklist 11). |
| FW-HW-008 | JP1 flashing procedure (3.3 V adapter, GPIO0 low at reset, baud 115200) is documented in `firmware/README.md`. | Done: the pinout is under "Hardware" and the steps under "First install over JP1"; `fw:backup` and `fw:flash` use 115200. |
| FW-HW-010 | A **hardware test** build (`-DTUBECLOCK_HWTEST`) reads the remaining pins (OQ-02) from the serial log, with no Wi-Fi, settings or secrets. It looks for the RTC at 0x68 on every pair of GPIO 4, 5, 12, 14, reading only, so the saved time is not disturbed. It tries the buzzer on GPIO 15 once as a level and once as a tone. It then logs every debounced change on GPIO 0, 2, 4, 5, 9, 10, 12, 14, 16, which it only reads. | Done: `firmware/hwtest/hwtest.ino`, built by `build.sh`, run on the clock 2026-11-07. |
| FW-HW-009 | The ESP8285 build uses flash mode DOUT (required for ESP8285) and the `1M (FS:64KB OTA:~470KB)` layout (OQ-21, decided), i.e. `--fqbn esp8266:esp8266:esp8285:eesz=1M64`. | Done (`build.sh`; DOUT is the board's default). The layout now runs on the clock, and `emulate.sh` gives the emulator the same 4 KB blocks. |
