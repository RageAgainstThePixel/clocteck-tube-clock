# OTA updates (`FW-OTA`)

The case has to be opened once for the first flash over JP1. After that, updates go over Wi-Fi.

| ID | Requirement | Status |
|---|---|---|
| FW-OTA-001 | ArduinoOTA listens on UDP/TCP port 8266 while Wi-Fi is connected, advertised over mDNS as `_arduino._tcp`, hostname = `FW_HOSTNAME`. | Done |
| FW-OTA-002 | OTA password = the API token (`FW_API_TOKEN`). ArduinoOTA uses MD5 challenge-response, so the token is not sent in clear. | Done |
| FW-OTA-003 | OTA is compiled out in the emulator build (`HOST_MOCK`). | Done |
| FW-OTA-004 | The image MUST stay small enough for OTA on 1 MB flash (FW-BUD-001). `build.sh` SHOULD print the image size and fail over the budget. | Done |
| FW-OTA-009 | `build.sh` and `emulate.sh` compute the version with `git describe --tags --always --dirty` and pass it as `-DTUBECLOCK_VERSION`. Releases are git tags `vX.Y.Z` on `main`; the image file is named `tubeclock-<version>.bin` so an OTA upload is traceable to a commit. | Done (`build.sh` copies `tubeclock.ino.bin` to `tubeclock-<version>.bin`; VER-013). |
| FW-OTA-005 | During an upload the tubes show progress at a fixed brightness: every tube scrambles through random digits in random colors, and they lock on a green 0 one at a time from the left, one per 1/6 of the image, redrawn at most every 80 ms. A verified image holds all tubes green for 500 ms, and a failed upload shows red for 1 s and goes back to the clock; a refused token shows nothing. After an update the device reboots and settings survive (FW-SET). | Done: `renderUpdateProgress`, host-tested (`testUpdateProgress`). On the clock on 2026-11-07, the brightness, hour format, active effect and a saved preset all survived an update. |
| FW-OTA-006 | `npm run fw:ota [host]` uploads the built image over ArduinoOTA without Python: a small Node client in `firmware/scripts/ota.mjs` that speaks the espota protocol (invitation on UDP 8266, MD5 challenge with the token, image over TCP), or `arduino-cli upload --protocol network` if that proves Python-free. It reads the token from `.env` and never prints it. It refuses an image not named `tubeclock*` without `--force`, since a test image has no Wi-Fi, and sends the image only to the clock's address. | Done: `firmware/scripts/ota.mjs` (OQ-12, Node). Ran on the clock 2026-11-07: the token was accepted, the clock verified the image and restarted, and it came back reporting the new version (`0.1.0-7-g1055b61`). |
| FW-OTA-007 | There is no online/vendor update route; `/update`, `/progress`, `/nVersion` are gone (FW-SEC-011). | Done |
| FW-OTA-008 | Stock firmware recovery: before the first flash the full 1 MB is read out and kept in the git-ignored `clock/backups/`, and `firmware/README.md` says how to write it back. The serial tool is `esptool-js` (Node); never the Python esptool (OQ-13, decided). `npm run fw:backup` / `fw:flash` wrap it. A backup never replaces an existing file, and `fw:flash` refuses to write until an intact backup is present. | Partial: backup and writes ran on the clock on 2026-11-06/07 from an earlier copy of these scripts. **Gap:** writing the stock image back has not been tried, and the scripts have not run from their new location on hardware. |
